# Библиотека, лайки, плейлисты, поиск

Подробности к `AGENTS.md` (общие правила проекта — там). Лайки (синхронизация, зеркала), обложки и описание плейлистов, импорт/экспорт, поиск (по тексту, ⌘K, недавние), выбор нескольких, «Отменить».

- **Картинки пользователей** (аватар, обложка плейлиста) — таблица `images` (base64, браузер заранее уменьшает фото `resizeImage` из `@/shared/lib` до 400–600 px JPEG), отдача `/api/images/:id` (только вошедшим, кэш навсегда — у новой картинки новый id). `saveImage` / `deleteOwnImage` / `isAllowedCoverUrl` в `server/utils/images.ts`; старая картинка удаляется при замене.
- **Плейлист: обложка и описание** — `PATCH /api/playlists/:id { name, description, cover }` (`cover`: нет — не трогать, `null` — коллаж, `{ url }` — обложка трека, `{ upload }` — фото). Своя обложка → `meta.customCover` (страница показывает её, а не коллаж). Окно `EditPlaylistDialog`: генерация обложки в браузере (`generateCover` в `shared/lib/cover-art.ts`: «как микс дня», градиент, волна, мозаика — цвета из обложек через прокси `/api/cover?size=`), описание — `describePlaylist` (из исполнителей и длительности, без внешних сервисов).
- **Лайк в обоих сервисах** (`like-sync.ts`: `mirrorLike` / `unmirrorLike`, таблица `like_mirrors`, настройка `users.like_both`, пункт меню «В любимые и в Spotify/Яндекс» → `/api/library/likes/mirror`): копия песни во втором сервисе ищется `findSpotifyMatch`/`findYandexMatch`; сверка лайков **пропускает зеркальные копии** (иначе на сайт пришёл бы второй экземпляр песни), снятие лайка снимает и копию.
- Поиск по тексту песни (`lyrics-search.ts`, `/api/search/lyrics`): кандидаты из поиска Яндекса проверяются по их тексту (в выдачу — только где фраза реально есть) + Genius API при заданном `NUXT_GENIUS_TOKEN`. LRCLIB по тексту **не ищет** (`q` — только название/исполнитель/альбом).
- Импорт/экспорт плейлистов (`playlist-transfer.ts`, `/api/transfer/*`, `/api/playlists/:id/export`): импорт копирует треки как есть; экспорт ищет чужие треки (`findSpotifyMatch` / `findYandexMatch`) и возвращает ненайденные. Яндекс: `users/{uid}/playlists/create` + `playlists/{kind}/change` (form: kind, revision, diff `[{op:'insert',at,tracks:[{id,albumId}]}]`). Spotify: `POST /me/playlists`, `POST /playlists/{id}/items`, нужен scope `playlist-modify-private` (старые подключения → 409 «переподключите»).
- **Лайки — двусторонняя синхронизация** (`like-sync.ts`): лайк/снятие на сайте сразу уходит в сервис (`syncLikeToService`); `syncLikes` сверяет с сервисом (фоном при открытии сайта и возврате на вкладку, не чаще раза в 5 мин на сервис — `accounts.likes_synced_at`; кнопка «Синхронизировать лайки» — принудительно): новое в сервисе → на сайт; было на сайте до прошлой сверки, а в сервисе нет → снимаем; новое на сайте, а в сервисе нет → досылаем. Треки Яндекса сравниваются по id трека **без альбома**. Если список Spotify обрезан (>1000) — снятий не делаем.
- Поиск: последние запросы — localStorage `search:recent` (запоминаются, если запрос «прижился» 1,5 с и что-то нашёл); подсказки — `/api/search/suggest` (Яндекс `/search/suggest?part=`, разбор мягкий).
- «Любимые треки» — `LikedCover :covers` (коллаж последних любимых + сердце; свои — `useLikedCovers`, у друга — `likedCovers` в профиле).
- «Выбрать треки» на панели коллекции → `provide(SELECT_ALL_TRACKS)` (`@/shared/lib`), `TrackList` (inject) выбирает все строки.
- Строка трека: долгое нажатие (телефон) и правая кнопка (компьютер) открывают меню «⋮»; click после удержания трек не запускает.
- **Выбор нескольких** (`TrackList`, пункт меню «Выбрать несколько»): выбор хранится по номерам строк (один трек может стоять дважды), сбрасывается при смене списка и Esc; панель действий телепортирована в body. Событие `remove` у `TrackList` — всегда массив треков.
- **«Отменить»** (`toast.show(text, tone, ms, { label, run })`): удаление из плейлиста — `batch-delete` возвращает места треков по порядку, `restore` вставляет их по возрастанию мест (после удаления позиции перенумеровываются без дыр — иначе вернутся не туда); снятие лайка — повторный лайк.
- «Любимые треки» можно изменить (обложка и описание, название фиксировано): `users.liked_cover_url / liked_description`, `/api/library/likes/meta`, тот же `EditPlaylistDialog liked`. Умные плейлисты — обложка `MixCover`, как у миксов.
- **Умный поиск ⌘K / Ctrl+K** (`widgets/spotlight`, состояние — `useSpotlight` из `@/shared/lib`): разделы/действия и свои плейлисты — на клиенте, любимые + треки в своих плейлистах + история — `/api/search/library` (`LibrarySearchResult`), каталог — `/api/search`. Стрелки/Enter/Esc, «Все результаты» переносит запрос на `/search`.
