# Карточка «Сейчас играет»

Подробности к `AGENTS.md` (общие правила проекта — там). Карточка и мини-плеер, переходы View Transitions, текст и караоке, полноэкранный режим, пластинки, визуализатор, видео, PiP, очередь «Далее».

- **View Transitions** (`experimental.viewTransition`): переходы между страницами; «перелёт» обложки — имя `cover-hero` (ставит `heroCover` из `@/shared/lib` на обложку нажатой карточки, постоянно — у обложки в шапке `CollectionView`) и `np-cover` (обложка мини-плеера, пока карточка закрыта ↔ обложка карточки). Одно имя — максимум у одного элемента на странице. Открытие/закрытие карточки — `useNowPlayingView().show/hide(animate)`; при уходе со страницы — `hide(false)` (иначе оборвётся переход Nuxt). **На телефонах (не `pointer: fine`) — без View Transition**, обычная CSS-шторка на `transform`: VT фотографирует весь экран, и на iPhone открытие тормозило. Карточка собирается заранее (`requestIdleCallback`) и дальше только показывается `v-show` — не собирать её в момент нажатия; видео и визуализатор — только пока открыта. Размытые фоны (карточка, `AmbientBackdrop`) — маленькая картинка с небольшим blur, растянутая `scale(4)`: так же на вид, в разы дешевле. На компьютере: Карточка (`np-sheet`) выезжает снизу, обложка (`np-cover`) летит поверх неё (`z-index` у групп задан явно — иначе браузер может положить обложку под карточку). На время перехода `html[data-vt=np-open|np-close]` снимает имена `page`/`cover-hero` у содержимого страницы — **иначе страница рисуется поверх карточки** (так и было «глючное» открытие на телефоне). Перед снимком ждём декодирования большой обложки (≤ 250 мс); у `UiCover` в мини-плеере и карточке `:fade="false"` — иначе на снимке пусто. Свайп вниз: шторка едет за пальцем (`--drag`), отпустили — уезжает вниз с того же места или пружинит обратно.
- **Вкладка «О треке»** в карточке (`TrackAbout` из `features/track-info`, общий запрос `useTrackDetails` с окном «Сведения»): дата выхода, место в альбоме, авторы (`writers` из ответа Яндекса на запрос текста — `yandexTrackWriters`), сводка об исполнителе (тот же кэш `u:ID:artist:…`, что у страницы исполнителя) и **«Другие версии»** (`track-versions.ts`, `/api/tracks/versions` → `{ versions, writers, isOriginal }`, кэш 6 ч): поиск Яндекса по «исполнитель + чистое название», по названию и (если поёт не автор) «автор + название»; вид — по пометкам в названии (remix, live, acoustic, slowed, sped, instrumental, remaster). Чужие записи без пометок (до 10) проверяются: исполнитель — сам автор → «оригинал»; авторы (`writers`, кэш сутки) известны у обеих — общий автор → кавер, иначе другая песня; авторов нет — **сравнение текстов** (тот же кэш `lyrics:<uid>`, что у карточки; ≥ 60 % общих слов от меньшего текста, в каждом ≥ 15 слов). Не удалось проверить — не показываем (одноимённых песен много, «Кавер» на них вводил в заблуждение). «Вы слушаете оригинал» — только если исполнитель совпал с автором (у групп обычно не совпадает — ничего не утверждаем). Та же запись с другого релиза отбрасывается. Блок вкладок карточки (`np__panels`) — постоянной высоты, содержимое листается внутри: иначе «О треке» вытягивал колонку и обложка уезжала.
- **Карточка «Сейчас играет» на телефоне**: обложка по высоте экрана (`100dvh − 430px − safe-area`, минимум 180 px) — название, управление и действия на первом экране; лайк — справа от названия. Жесты: обложку влево/вправо — следующий/предыдущий (в `touchend`), двойное касание — лайк с сердечком, вниз — свернуть; направление фиксируется по первым 10 px. Обложка меняется только после загрузки новой картинки (`shown`, не дольше 1,2 с), старая и новая лежат в одной ячейке grid и едут одновременно (без `mode="out-in"` — иначе пустой промежуток). Размытые фоны — `useLoadedSrc` (иначе фон пропадает при быстром листании).
- **Смена трека в названии** — `UiSwap` (`swap-key` = uid, `dir` = next/prev по изменению `index`): старое уезжает вверх, новое въезжает снизу, оба в одной ячейке grid (мини-плеер; карточка — в сторону `slideDir` обложки).
- Мини-плеер на телефоне: полоса касания над нижней полоской прогресса — перемотка пальцем с подсказкой времени.
- Мини-плеер на телефоне: свайп влево/вправо — следующий/предыдущий трек (`next/previous` вызываются в `touchend` — это жест, iOS разрешит звук); после горизонтального жеста `click` не открывает карточку.
- Акцент «Из обложки» (`data-accent="cover"`, `useCoverAccent` в switch-theme, `coverAccent` в shared/lib): цвет считается на canvas из копии обложки через `/api/cover` (прокси только для доменов обложек Яндекса/Spotify — иначе браузер не даст читать пиксели); выставляет `--accent-dark/--accent-light` на `<html>`, они зарегистрированы через `@property` и плавно анимируются.
- **Текст песни** в карточке — кнопка «Текст песни» в ряду действий меняет обложку на `LyricsPanel` в той же ячейке (`np__stage`) того же размера (на телефоне — во всю ширину, высота как у обложки): ниже ничего не сдвигается; выбор помнится (localStorage `np:lyrics`). На тексте свайпы обложки и сворачивание карточки отключены (там прокрутка). Загрузка — строки-заглушки.
- Полноэкранный режим «Сейчас играет» (`widgets/now-playing/ui/ImmersiveView.vue`): «живой» фон `LivingBackground` (4 пятна-градиента из `coverPalette` обложки, цвета — `@property`, плавно перетекают; на компьютере с анализатором — «дыхание» от басов `--lb-beat`), текст `LyricsPanel karaoke`. Телефон: сверху обложка и название, по центру текст, снизу прогресс и кнопки (строка сетки текста `minmax(0, 1fr)` — иначе текст заезжает под кнопки). Компьютер: обложка «дышит» слева, текст справа, управление прячется. F — открыть карточку, ещё раз F — режим, Esc — выход.
- **Заливка текста по ходу песни** (`model/karaoke.ts`, `useKaraokeFill`): время слов — из расширенного LRC (`LyricsLine.words`, `parseLrc` разбирает `<мм:сс.xx>`), иначе строка делится по слогам (≈0,28 с на слог, не дольше следующей строки). Позиция досчитывается между обновлениями плеера; каждый кадр пишется только `--w` у слов текущей строки (при смене строки инлайн-значения снимаются). Буквы (`lyrics__c`) заливаются по очереди: `--f` из `--w`/`--p`/`--n` в CSS, «пик» — подъём, увеличение и свечение акцента.
- Текст песни: `overflow-x: hidden` и `touch-action: pan-y` (увеличенная строка не делает блок «ездящим» вбок), у строк нет рамки фокуса от касания.
- Фон `<html>` и `theme-color` — с оттенком обложки (`--ambient-tint` от `AmbientBackdrop`): полоска статус-бара iPhone не чёрная, а в тон фону.
- Видеообложки (`entities/track/ui/TrackVideo.vue`, `/api/yandex/track-video/:id` → поле `backgroundVideoUri` трека): формат ссылки не задокументирован — видео показывается, только если реально заиграло.
- **Визуализатор** (`lib/analyser.ts`, `ui/AudioVisualizer.vue`): только компьютер и движок Яндекса (звук Spotify под DRM). `<audio>` грузится с `crossOrigin="anonymous"`; если CDN не отдал CORS — визуализатор выключается до перезагрузки, трек перезапускается без CORS. Элемент подключается к AudioContext **только когда уже играет с CORS и контекст запущен** — подключённый элемент звучит только через контекст (иначе тишина). Не ломать этот порядок.
- **Караоке в Safari** — без `text-shadow` у букв (`@supports (font: -apple-system-body)` и `pointer: coarse`): WebKit не стирал свечение увеличенной буквы, оставались фиолетовые полоски в конце строк. Там «вспышка» — цветом акцента.
- **Текст песни — одно хранилище** (`widgets/now-playing/model/lyrics.ts`, `useCurrentLyrics`: модульный синглтон в своём `effectScope`, один запрос на песню, кэш по uid, ответ проверяется `clean()` — кривой формат = «текста нет»). Раньше каждый компонент заводил свой `useAsyncData` с общим ключом: появление панели запускало загрузку, полноэкранный режим на время загрузки показывал панель, у песни без текста убирал — по кругу, приложение падало. Полноэкранный режим меняет раскладку только когда загрузка закончилась (`lyricsShown`).
- **Полноэкранный режим**: телефон — компактный, переключатель «обложка / текст» в шапке (localStorage `imm:text`), без текста — только обложка; компьютер — обложка слева, текст справа, без текста — обложка по центру. Обложка — квадрат `imm__frame` (`position: relative`, свои границы: `TrackVideo` — `position: absolute; inset: 0` и без этого растягивалась на весь экран). Видеообложка здесь — только на компьютере; карточка под режимом не рисуется (`.np.is-immersive > :not(.imm)`), её видео выключено.
- `useKaraokeFill` — флаг `alive`: отложенный `start` после размонтирования панели заводил вечный цикл кадров. `LivingBackground` на телефоне меняет цвета под притушенными пятнами (`is-swapping`, прозрачность), а не переходом `@property` — тот перерисовывал огромные пятна каждый кадр.
- Караоке в Safari / на телефонах: буквы и строки без `scale`/`transform`/`filter`/`text-shadow` (`karaoke-flat`) — WebKit не стирал то, что выходило за границы, и в конце строк оставались полоски.
- **«Обложки как пластинки»** (Оформление; cookie `vinyl` — boolean: `useCookie` сам разбирает значение, строка '1' стала бы числом): `FlipCover` (widgets/now-playing) — спереди обложка (слот), сзади `UiVinyl`; переворот БЕЗ backface-visibility (в Safari изнанка обложки просвечивала зеркально): поворот до ребра, смена стороны на середине, доворот; со включённой темой пластинка всегда видна из-за обложки-«конверта» (конверт 74 % ширины, пластинка справа: на паузе ~треть, пока играет — до половины и крутится; `flip__peek`) (бороздки — `repeating-radial-gradient`, обложка-«яблоко», крутится 1,8 с/оборот, только пока играет и видна). Значение темы — общий `useState` поверх cookie (отдельные `useCookie` не видели изменения из настроек до перезагрузки). Сторона общая (`useState('np:flipped')`) для карточки и полноэкранного режима. Карточка: одиночное касание/клик переворачивает с задержкой 320/250 мс (второе касание — лайк, переворот отменяется); полноэкранный режим — сразу по нажатию. У обложки полноэкранного режима — наклон за курсором, блик и свечение, как в карточке.
- **Мини-плеер поверх окон** (`widgets/pip-player`, `useDocumentPip` в `shared/lib/document-pip.ts`): Document Picture-in-Picture — только Chrome/Edge/Яндекс Браузер на компьютере (кнопка в плеере появляется после гидрации, если API есть; клавиша P). Содержимое — `<Teleport>` в `body` окна (тот же JS, плеер общий). Стили: файлы CSS подключаются **ссылкой** (в них относительные адреса шрифтов `./inter-….woff2` — скопированный текстом CSS искал бы их от корня), встроенные `<style>` копируются текстом; атрибуты `<html>` (тема, акцент) синхронизирует MutationObserver. Клавиши вкладки в окно не доходят — у окна свои (пробел, стрелки). **Playwright:** `page.route`/`ctx.route` вешает все загрузки окна PiP — перед открытием окна `unrouteAll()`.
- **Караоке режет слова по графемам** (`Intl.Segmenter`), не по кодовым точкам: огласовки хинди/тайского, оторванные от буквы, рисовались с пунктирными кружками.
- **Очередь «Далее»** в карточке: у строки — «Сыграть следующей» (`player.playNextAt(i)` — переставляет, не дублирует) и «Убрать» (`player.removeAt(i)`, убирает и из исходного порядка для «перемешать»); на компьютере — перетаскивание (HTML5 drag, `player.moveInQueue(from, to)`). Номера — в `queue`, только после играющего. Пульт (`controlling`) очередь не правит — у устройств нет таких команд, кнопки скрыты.
