# Подборки и радио

Подробности к `AGENTS.md` (общие правила проекта — там). Миксы дня/недели, умные плейлисты, жанры, станции, «Моя волна», миксы по годам, фильтр вкуса, пропуски.

- «Вышло новое» (`releases.ts`, `/api/releases`, кэш 6 ч): релизы за 90 дней у любимых исполнителей (`tasteOf` из `mixes.ts`), Яндекс `brief-info.lastReleases` + `direct-albums`; без `releaseDate` релиз не показывается.
- «Микс дня» / «Открытия недели» (`mixes.ts`, `/api/mixes/{daily|discover}`, страница `/collection/mix:…`): собираются из истории и лайков, новые треки — радио Яндекса по исполнителю и похожие исполнители (`brief-info`). Хранятся в таблице `mixes` (один набор на всех устройствах до конца дня/недели по Москве), сборка детерминирована по зерну `userId:kind:period`.
- **Умные плейлисты** (`smart-playlists.ts`, `/api/smart`, `/collection/smart:KIND`): liked-month | top | forgotten | not-liked | new-week — правила по истории (год) и лайкам, считаются при открытии. **История** — `/history`, API `/api/history/log?q=&before=` (курсор по времени, поиск ILIKE по названию/исполнителям). **Совпадение вкусов** — `/api/friends/:id/match` (косинус по весам исполнителей: лайк 2, прослушивание за 90 дней 1; `enoughData` — минимум 3 исполнителя у каждого), «Общее у нас» — `/collection/taste:UID`.
- Обложки «Микс дня» / «Открытия недели» — `MixCover` (одна обложка из подборки + полоса её цвета с названием, как у Spotify); пока подборка дня не собрана — обложки прошлой или любимых. Коллажи `PlaylistCover` пропускают битые картинки (сервер отдаёт до 8 обложек с запасом).
- **«Больше не предлагать»** (`useDislike` из `features/track-actions`, `player.dislike`): трек убирается из оставшейся очереди, попадает в localStorage `player:blocked` (радио его отфильтровывает в `fetchMore`), в Яндекс уходит дизлайк `/api/yandex/dislike` (`undo: true` — снять).
- **Плейлисты по жанрам** (`genre-mixes.ts`, `/api/genres` — каталог, `/api/genres/:stationId` — плейлист, `/collection/station:genre:rock`, страница `/genres`, сущность `entities/station`: `GenreTile`, `useGenres`): станции Яндекса `/rotor/stations/list` (группы genre/mood/epoch/activity, разбор мягкий, кэш 12 ч); «Жанры дня» — 8 станций по зерну `userId:день` (на главной и в поиске до ввода). Плейлист — до 8 порций треков станции (продолжение по последнему треку) без уже лайкнутого, хранится в `mixes` (kind `station:…`, в базе text) до конца дня по Москве, «Пересобрать» — `?fresh`. Только Яндекс (без него — 409, на клиенте не запрашивается).
- **Добор треков со станций — `stationFill`** (`radio-fill.ts`): сначала **сессии радио** (`POST /rotor/session/new { seeds, includeTracksInResponse }` → `/rotor/session/{id}/tracks { queue }`, как у нынешних клиентов Яндекса; сессия пользователя по станции живёт в памяти 20 мин, живой поток её продолжает — `continueSession`). Запасной путь — старый `/rotor/station/{id}/tracks?queue=`: **без `feedback trackStarted` он раз за разом отдаёт ту же порцию** (подборки застревали на ~10 песнях), поэтому шлём обратную связь и идём «вширь». Дубли — по uid и `songKey`. Подборки и радио берут треки станций только через неё. Формат сессий не документирован — разбор мягкий; на живом Яндексе не проверялось агентом.
- **Живой поток** (`/api/radio`): клиент шлёт `seed` (последний трек очереди) и `exclude`; без `seed` «Моя волна» отдавала первую порцию, она вся была в очереди — и музыка останавливалась. Недавно звучавшее (12 ч) не повторяется; станция выдохлась → запасные (`track:` последнего → его исполнитель → волна); всё уже звучало → разрешаем повтор. В продолжение подмешивается любимое тех же исполнителей из обоих сервисов (`familiarFor`, ~каждый 5-й). Клиент заказывает продолжение за 3 трека до конца — у любой очереди (альбом, плейлист), не только у радио; пустой ответ — ещё одна попытка.
- **Версия сборки подборок** (`BUILD` в `mixes.ts` и `genre-mixes.ts`) входит в `period`: поменяли правила — повысить, подборки текущего дня/недели пересоберутся. «Микс дня» — до 60 (знакомое чередует Яндекс/Spotify, новое — радио 8 исполнителей + «похожее на» любимые треки, ≤ 4 песен исполнителя), «Открытия» — до 50 (16 лучших + 8 случайных кандидатов; мало — добор волной с незнакомыми исполнителями), жанр — до 45 новых (≤ 3 на исполнителя) + каждый 5-й — любимое тех же исполнителей. Жанр/эпоха у пользователя со Spotify — каждый третий трек из поиска Spotify (`spotifyDiscover`, `SPOTIFY_GENRES` — тег станции → `genre:"…"`, эпохи → `year:`; настроения/занятия — без Spotify). Каталог станций: у поджанров Яндекса повторяются значок и цвет — `distinctLook` оставляет значок только первой (у остальных `GenreTile` рисует крупную букву контуром) и даёт повторам свободный цвет из `PALETTE`. Плитки миксов (`BlendTiles`) — в стиле `GenreTile`: цифры десятилетия контуром в углу. «Жанры дня» — 4 «по вкусу» (жанры любимых исполнителей из brief-info + `/rotor/stations/dashboard`), остальное — по квотам групп; кэш на день.
- **«Миксы по годам» — поток из двух сервисов** (`shared/utils/blends.ts` `BLEND_PRESETS` — общий для сервера и клиента; `server/utils/blend-mixes.ts`; `/api/radio { station: 'blend', id }`; плитки `BlendTiles` из `features/start-wave` на главной и в «Жанрах»): Яндекс — станция эпохи/жанра из каталога (теги-кандидаты, эпоха — ещё и по названию; нет — «Моя волна»), отбор по году (`Track.year` — год альбома, в базе не хранится; у станции эпохи — мягко); продолжение — от последнего трека **Яндекса** в `exclude` (последним может быть Spotify). Spotify — поиск `year:FROM-TO` (+ `genre:"…"`, не нашлось — жанр словом) с 3–4 случайных мест выдачи до 400. Источники через один (кто первый — случайно), одна песня из двух сервисов — одна; подключён один сервис — поток из него.
- **Фильтр подбора — `tasteGuard` / `keepToTaste`** (`taste-filter.ts`): через него проходят радио, миксы по годам, жанры, «Микс дня», «Открытия». Отсекает: скрытых исполнителей (`blocked_artists`, «Не предлагать «исполнитель»» в меню трека → `/api/library/blocked-artists` GET/POST/DELETE, список — «Скрытые исполнители» в настройках, `HiddenArtists`); «не мою» письменность (латиница/кириллица — всегда, остальные — только если есть в библиотеке ≥ 2 раз); индийскую эстраду латиницей (лейблы/исполнители `INDIAN`, если такой нет в библиотеке); **надоевшее** — ≥ 3 прослушиваний за неделю, ≥ 2 пропусков за месяц, исполнители, которых в основном пропускают (≥ 4 пропусков). Новые таблицы отдельные, без них подбор работает (запросы в `catch`).
- **Пропуски и обратная связь** (`/api/radio/feedback { track, type: skip|finish, playedMs, station }`): плеер (`reportListen` в `next()`) шлёт только для радио (`radioSource` задан): < 30 с (и ≥ 1 с) — skip, естественный конец — finish. Сервер пишет пропуск в `skips` и для трека Яндекса в волне/станции шлёт `/rotor/station/{id}/feedback` (skip / trackFinished) — волна Яндекса учится.
- **«Моя волна»** (`/api/radio`, station: wave): старт — 24 трека, продолжение за 3 до конца; состав: новое из Яндекса + новое из Spotify в жанрах пользователя (`tasteSpotifyGenres`, каждый третий) + любимое из обоих сервисов, не звучавшее 3 дня (каждый пятый). Миксы десятилетий тоже ищут в Spotify по жанрам пользователя, а не «всё популярное за годы» (приносило чужую музыку). В очереди карточки — пометка «Spotify» и «подбор продолжится сам».
- **Плитки станций и миксов** — миксин `color-tile` (+ `color-tile-name`, `color-tile-glyph`): поверхность `--c-surface` со свечением цвета, приглушённого к акценту (`--tint`), значок/цифры — `--ink`. Белые значки Яндекса — маской (`mask-image`) через `/api/cover` (маске нужен свой домен — CORS); загрузку проверяет `new Image()` — **не `<img hidden>` в разметке**: глобальный стиль `img` перебивал `hidden`, белый значок вставал поверх названия. Нет значка — только название и свечение (буквы-заглушки выглядели плохо).

- **«Похожее на трек» без Яндекса** (`/api/radio`, station: similar, нет активного Яндекса; `server/utils/similar-radio.ts`): Last.fm Similar от `seed.artists` (имена одинаковы для Spotify/Яндекс-треков, резолв id не нужен), основной исполнитель первым, фиты — запасные зёрна. Запасной ход при продолжении (<5 треков) — Similar по зёрнам Вкуса (`waveLastfmTracks`), а не `user:onyourwave`. Всё через `tasteGuard`. Грабля: без seed ветка не включается (идёт обычная логика).
- **«Моя волна» без Яндекса** (`/api/radio`, station: wave, нет активного Яндекса; `server/utils/wave-lastfm.ts`): rotor-сессии нет, поэтому непрерывность — расширяющаяся выборка зёрен Вкуса. Пул — топ-40 исполнителей `tasteOf(90)`, порция — срез из 5 через Last.fm Similar (`similarTracksForMany`); номер среза = `floor(exclude.length / 20)`, окно идёт по кругу (зёрна кончились — те же исполнители, но треки из `exclude` отсеиваются). Не более 3 треков исполнителя. Состав как у яндексовой волны: жанровая добавка Spotify (каждый третий) + любимое (каждый пятый); Last.fm пуст — деградация на любимое + Spotify-жанры. Всё через `tasteGuard`. Грабля: Last.fm-источник без Яндекса ничего не знает про «сессию» — только `exclude` клиента, поэтому срез выводится из его размера.
- **Жанры Spotify без Яндекса** (`tasteSpotifyGenres` → `spotifyArtistGenres`, `taste-filter.ts`): нет Яндекса — `genres` из `GET /artists/{id}` для топ-12 исполнителей `tasteOf(90)` со `spotifyId`, 4 самых частых; кэш тот же (12 ч). Жанры Spotify уже родные для `genre:"…"`, без `spotifyGenreForTag`. Без `spotifyId`/жанров или при ошибке запроса исполнитель молча пропускается (пусто → поиск только по годам). С Яндексом поведение прежнее (теги станций).
